# 用华为云码道(CodeArts)开发一款「泰拉瑞亚」式 2D 沙盒生存游戏

> 面向大学生的 AI 辅助编程实操教学案例
> 全程使用华为云码道代码智能体,从一句自然语言需求出发,生成并迭代出一个可玩、可验证、可扩展的 2D 沙盒游戏。

---

## 一、案例简介

本案例的最终成果是一款 Terraria(泰拉瑞亚)风格的 2D 侧视沙盒生存游戏,纯 HTML5 Canvas + 原生 JavaScript 实现,无需任何第三方依赖,双击 `index.html` 即可运行。

**游戏特性:**

- 随机生成可破坏地形(噪声算法:起伏地表、洞穴、煤/铁/金/水晶四层矿脉、树木、低洼水潭)
- 挖掘与建造:镐子分级(木→石→铁→金),方块自由放置,可在水中填埋
- 合成系统:工作台、火把、四档镐、四档剑与水晶剑,高级配方需靠近工作台
- 昼夜交替:日月起落、星空、天色渐变、火把光晕照明
- 夜晚怪物 AI:僵尸近战追踪 + 骷髅弓箭手远程抛物线射箭,天亮一同自燃
- 简单水体:山谷水潭,水中移动变慢、可游泳(按住空格上浮),有氧气条,耗尽溺水
- 本地存档:每 30 秒自动存档至 localStorage,开始界面可"继续游戏"恢复进度
- 泰拉瑞亚式 HUD:红心生命条、氧气条、10 格快捷栏、金币计数、天数指示、F3 帧率显示

**项目结构:**

```
terraria-game/
├── index.html          # 页面结构、样式、UI 面板(开始/死亡/背包/合成)
├── game.js             # 全部游戏逻辑(约 1600 行)
├── test-headless.js    # 无头冒烟测试(Node.js 运行)
└── README.md           # 本文档
```

## 二、教学目标

完成本案例后,你将能够:

1. 用**结构化自然语言**向 AI 智能体描述一个完整软件需求;
2. 理解码道智能体「技能匹配 → 代码生成 → 自动验证」的工作流程;
3. 对 AI 生成的代码进行**运行验证、语法检查、自动化测试**;
4. 读懂中等规模(千行级)游戏代码的核心模块:噪声地形生成、AABB 物理碰撞、2D 光照、简单怪物 AI;
5. 通过**迭代提示词**让 AI 在已有代码上增加新功能;
6. 使用 Git 将项目推送至 GitCode 远程仓库。

**前置知识:** 基本的计算机操作、了解 JavaScript 语法者更佳(非必需)。

## 四、实操步骤

### 步骤 1:用一句话描述需求(提示词)

在码道对话框中输入本案例的原始需求:

```
生成一个类似泰拉瑞亚的2D侧视沙盒生存游戏:随机生成可破坏地形,
玩家挖掘资源、建造房屋、制作工具武器,夜晚会生成僵尸,有昼夜交替。
游戏的玩法和游戏的画面效果尽量贴近泰拉瑞亚。
```

**提示词要点(教学讲解):**

- **有参照物**:「类似泰拉瑞亚」让 AI 直接对齐成熟产品的玩法与画风,胜过千言万语;
- **列核心机制**:随机地形、挖掘、建造、合成、怪物、昼夜,一句话一个机制;
- **明确质量要求**:「尽量贴近泰拉瑞亚」约束了完成度,而不是一个简陋 Demo。

> 课堂讨论:如果把提示词改成「写一个 2D 游戏」,产出会差在哪里?

### 步骤 2:观察智能体的工作过程

码道收到需求后会自动执行(请在课堂上引导学生观察):

1. **技能匹配**:命中 `frontend-design`(前端应用生成)技能,确定像素复古的美术方向;
2. **生成代码**:产出 `index.html`(页面+UI)与 `game.js`(游戏逻辑);
3. **自动验证**:执行 `node --check game.js` 做语法检查;
4. **自动测试**:编写并运行 `test-headless.js` 无头冒烟测试,模拟 600 秒游戏运行(覆盖完整昼夜循环与僵尸生成),确认无运行时异常;
5. **交付说明**:给出玩法介绍与操作按键。

### 步骤 3:运行游戏

直接用浏览器打开 `index.html`,或在码道中让它执行:

```
预览一下
```

操作方式:

| 按键 | 功能 |
| --- | --- |
| A / D | 左右移动 |
| 空格 / W | 跳跃 · 水中按住游泳上浮 |
| 鼠标左键 | 挖掘(持镐)/ 放置(持方块)/ 攻击(持剑) |
| 滚轮 / 1~0 | 切换快捷栏 |
| E / Tab | 背包与合成 |
| F3 | 帧率显示开关 |
| H | 帮助 |

**试玩验收清单:**

- [ ] 地表高低起伏,有树木;向下挖能遇到洞穴
- [ ] 挖到的土块/石块/木材进入背包,可在快捷栏选中并放置
- [ ] 用木材合成工作台并放置,靠近后可合成石镐
- [ ] 放置火把后周围被照亮
- [ ] 天黑后出现僵尸,用剑击杀后金币增加
- [ ] 天亮后僵尸自燃消失,天数 +1
- [ ] 深层可见紫色水晶矿,木/石/铁镐挖不动,金镐可挖,能合成水晶剑(伤害 35)
- [ ] 夜晚除僵尸外还有骷髅弓箭手,保持距离并抛物线射箭
- [ ] 山谷有水潭,跳入后移动变慢、按住空格上浮,氧气条耗尽会持续溺水掉血
- [ ] 玩一会儿刷新页面,开始界面出现"继续游戏",点击后世界/背包/金币/天数恢复

### 步骤 4:运行自动化验证

```bash
cd terraria-game
node --check game.js     # 语法检查
node test-headless.js    # 无头冒烟测试:模拟 600 秒游戏逻辑
```

预期输出:

```
SYNTAX OK
SMOKE OK: 600s 模拟无异常
```

**教学讲解:** `test-headless.js` 用「桩(Stub)」替代 DOM 与 Canvas 接口,让游戏代码脱离浏览器也能跑通主循环。这是测试 UI 密集型代码的常见思路——**把副作用关进笼子,只验证逻辑**。

## 五、核心代码导览

`game.js` 各模块速览(课堂讲解用):

| 模块 | 内容 | 关键思路 |
| --- | --- | --- |
| 常量与图块 | `T` 枚举定义 13 种图块(草/土/石/矿/树/火把等),`TILEINFO` 定义硬度、镐等级、掉落物 | 数据驱动,加新方块只需加表项 |
| 噪声 | `hash1/hash2/noise1/noise2/fbm` | 哈希 + 平滑插值 + 分形叠加,无需外部库 |
| 世界生成 | `genWorld()` / `veins()` | 1D 噪声定地表高度 → 2D 噪声掏洞穴 → 随机游走画矿脉 → 概率种树 |
| 物理 | `collides()` / `moveEntity()` | AABB 与图块网格碰撞,先 X 后 Y 分轴解算 |
| 挖掘/放置/攻击 | `handleMouse()` | 手持物决定左键行为;镐等级不足时给出提示 |
| 僵尸 AI | `updateZombies()` | 夜间在屏幕外生成,朝玩家移动,遇墙跳跃,天亮自燃 |
| 光照 | `drawDarkness()` | 天空光(按昼夜亮度)+ 火把半径光晕 + 玩家微光,逐格叠加暗色遮罩 |
| 渲染 | `drawTile()` / `drawHumanoid()` | 哈希驱动的伪随机纹理像素;矩形拼装角色 |
| 合成 | `RECIPES` / `canCraft()` | 配方表 + 材料检查 + 工作台 proximity 检测 |
| 主循环 | `loop()` | 固定时间步(60Hz)更新 + 每帧渲染 |

## 六、课堂实操任务(迭代开发)

以下任务按难度分级,学生**不手写代码**,而是通过码道对话完成,练习「在已有项目上迭代」的提示词写法。

### 基础任务

**任务 B1:新增一种矿物「水晶」**

参考提示词:

```
在 game.js 中新增一种深层矿物"水晶":比金矿更稀有,呈紫色,
挖掘需要金镐,可合成一把伤害 35 的水晶剑。
```

验收:地下深层可见紫色矿石;木/石/铁镐挖不动;能合成水晶剑。

**任务 B2:增加坠落的星星(回血道具)**

```
参考泰拉瑞亚,夜晚天空偶尔坠落"落星",玩家碰到后回复 10 点生命,
有粒子特效和音效。
```

### 进阶任务

**任务 A1:本地存档**

```
为游戏增加自动存档:每 30 秒把世界图块数组(可用 RLE 压缩)、
背包、金币、游戏时间存入 localStorage,开始界面增加"继续游戏"按钮。
```

教学点:让 AI 处理序列化格式设计,学生检查刷新页面后世界是否复原。

**任务 A2:新怪物「骷髅弓箭手」**

```
新增怪物骷髅弓箭手:夜晚与僵尸一起生成,与玩家保持 8 格距离,
每 3 秒射出一支箭(抛物线),箭命中玩家造成 8 点伤害。
```

教学点:抛射物需要独立的实体数组与重力模拟,观察 AI 如何复用现有物理模块。

### 挑战任务

**任务 C1:简单水体**

```
在地形低洼处生成水:水占半格高度,玩家在水中移动变慢、可以游泳(持续按住空格上浮),
有氧气条,耗尽后持续掉血。
```

**任务 C2:性能优化**

```
分析当前渲染性能瓶颈,把光照计算和图块绘制优化到 1080p 下稳定 60 FPS,
给出优化前后的帧率对比方法。
```

教学点:先让 AI 给出测量方案(如帧率统计),再谈优化,避免"没有数据的优化"。

## 八、常见问题(FAQ)

**Q1:游戏打开是黑屏?**
按 F12 打开浏览器控制台查看报错;多数是本地文件被浏览器安全策略拦截,尝试更换浏览器或用 `npx serve` 起一个本地服务。

**Q2:AI 生成的新功能把原有代码改坏了?**
这是迭代开发的常态,也是课程重点:先用 Git 提交一个可运行版本再让 AI 改;出问题后 `git diff` 定位,或 `git checkout -- .` 回滚。

**Q3:如何让 AI 只改一小块而不重写整个文件?**
在提示词中明确范围,例如:「只修改 `updateZombies` 函数,不要动渲染部分」。码道默认做最小编辑,但明确约束更稳妥。

**Q4:手机/平板上能玩吗?**
当前版本仅支持键鼠。可作为扩展任务:「为游戏添加触屏虚拟摇杆与按钮」。

**Q5:想做成多人联机?**
超出本案例范围,但可作为课程设计延伸:WebSocket 同步世界状态,建议先把世界生成改为「同种子确定性生成」。

## 十、结语

本案例展示的不是「AI 替人写代码」,而是一套**人机协作的工作方式**:

> 人负责定义问题、拆解需求、验证结果;AI 负责高效产出实现。

大学生需要训练的,正是「描述清楚要什么」与「判断做得对不对」这两种能力——它们比记住任何语法都更接近未来工程师的核心竞争力。
